# v0.24: Explicit Swingometer model semantics

## Summary

v0.24 makes the Swingometer's existing deterministic behavior model legible before the user changes a vote. It does not alter scenario arithmetic.

## What changed

- A visible Model Contract accompanies Turnout, Preference, and Third Party controls.
- Each contract states the input population, exact change, preserved quantities, and feasible boundary.
- Pennsylvania, Michigan, and Wisconsin show distinct turnout-denominator wording.
- Two-party preference endpoints now display the full calculated feasible movement in both directions.
- Third-party endpoints show the selected candidate's removable share and available gain capacity.
- Turnout shows requested versus realized additions and the exact Harris/Trump split.
- Preference and third-party explainers show requested versus realized exchanges.
- The interface labels every operation as a scenario assumption, not a forecast.

## Preserved guarantees

- The zero-change scenario still reproduces the certified baseline.
- Every result remains integer-exact.
- Preference and third-party operations preserve total ballots.
- Preference preserves all third-party totals.
- Turnout uses only documented local capacity.
- Existing scenario URLs and recipes remain compatible.

## Verification

The release adds a state-contract model suite and a focused browser journey covering all three operation explanations. See [`docs/review/v0.24-swingometer-semantics/VERIFICATION.md`](../review/v0.24-swingometer-semantics/VERIFICATION.md).
