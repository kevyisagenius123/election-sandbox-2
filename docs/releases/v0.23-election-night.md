# v0.23: Integrated three-state Election Night

Date: 2026-08-22

## Overview

Election Night is now a mode of the existing Sandbox laboratory rather than a separate page or replacement map. A user can build a Pennsylvania, Michigan, or Wisconsin counterfactual in the Swingometer and then watch that exact result emerge through detailed local returns on the same mounted 3D map.

The visible replay includes only jurisdictions with an admitted detailed foundation:

- Pennsylvania VTD-linked model units;
- Michigan exact-cycle precinct reporting units;
- Wisconsin reconstructed detailed wards.

The other 48 jurisdictions remain inert. The interface does not fabricate county or statewide fallback returns for unsupported states.

## User-facing updates

### One continuous Atlas workspace

- Election Night and the Swingometer share `/app/`, map state, camera, and geographic selection.
- State, county, and reporting-unit colors derive from currently reported votes.
- Unreported geography stays neutral.
- The newest return receives a restrained gold highlight.
- The upper-right PA/MI/WI desk is a read-only summary rather than a second control surface.

### Shared bottom command dock

The resizable dock now owns:

- play, pause, reset, and next return;
- 0.1x, 0.5x, 1x, 4x, and 12x playback speeds;
- timeline seeking;
- live three-state summaries;
- count-direction controls;
- geographic return inspection;
- methodology and evidence explanations;
- the handoff back to the Swingometer.

It supports collapsed, working, and expanded positions on desktop and a compact two-row mobile layout.

### User-directed count behavior

Users can change:

- statewide count duration;
- mixed, smaller-area-first, or larger-area-first reporting order;
- timing volatility;
- burst and stall intensity;
- state activation delays;
- deterministic seed.

Four built-in candidate-blind profiles provide useful starting points: Balanced count, Rural opening, Metropolitan opening, and Volatile waves.

Custom chronologies can be named and saved in browser-local storage. They can be reloaded, updated, and deleted without affecting the underlying election scenario.

### County timing exceptions

An explicit county override can:

- move a county's activation window earlier or later;
- shorten or lengthen its count window.

Overrides cannot inspect candidate shares or change vote totals. The compiler validates unique county keys, five-digit county FIPS identifiers, bounded start shifts, and bounded count lengths.

### Pre-apply chronology preview

Before restarting, the director shows:

- planned PA, MI, and WI activation and finish windows;
- the number of local exceptions in each state;
- whether the draft differs from the chronology currently running.

The preview is explicitly a planning view. Deterministic local waves, stalls, and exceptions decide the exact return times inside those windows.

### Redesigned editorial home

The home page now adapts the original Sandbox's map-led storytelling to the warm Atlas visual system. It introduces the product through three jobs, Model, Direct, and Understand, followed by a four-step analyst workflow and an honest explanation of the different Pennsylvania, Michigan, and Wisconsin data contracts.

## Replay architecture included in this release

This push also records the previously uncommitted v0.21 and v0.22 replay foundation:

- immutable locked endpoints and canonical fingerprints;
- detailed Pennsylvania and Michigan compilers;
- generic detailed, coarse, and hybrid jurisdiction contracts;
- deterministic national composition and exact five-candidate conservation;
- pure replay reducer and checkpoint seeking;
- reported-state analytics derived only from applied votes;
- logical playback controller;
- sanitized current-knowledge observation boundary;
- worker-owned replay runtime;
- evidence, benchmark, decision, and verification records.

The visible three-state experience uses a dedicated PA/MI/WI worker so unsupported coarse states cannot enter the map presentation.

## Deliberate omissions

This release does not add:

- estimated outstanding vote;
- Decision Desk projections or state calls;
- hidden-outcome mode;
- backend accounts or memberships;
- live rooms;
- server-rendered video;
- public detailed-state data clearance.

State color means the current reported-vote leader, never a projection or call. The reporting chronology is a deterministic synthetic reconstruction unless separately documented otherwise.
