# v0.27 plan: Swingometer explanation

Date: 2026-08-23

## Objective

Make the Swingometer explain a scenario as quickly as it creates one. The product should connect an explicit control change to exact local movement and then to the Electoral College without turning the laboratory into a dashboard wall.

## v0.27A: Causal scenario hierarchy

Status: implemented

- Produce a deterministic, headless scenario-explanation contract from the accepted scenario delta ledger.
- Identify the dominant operation by absolute signed Harris minus Trump margin movement.
- Identify the strongest supporting county, strongest local offset, and strongest mapped local unit.
- State whether the modeled result changed the state winner and how many EV changed hands.
- Present the explanation as one compact three-step chain inside Contributors.
- Preserve the exact operation waterfall and ranked geography ledger below it.
- Verify desktop and 390 px layouts without adding a chart or another renderer.

## v0.27B: Geographic third-party behavior

Status: next

- Replace the current statewide proportional third-party exchange with an explicit, deterministic geographic allocation contract.
- Preserve exact candidate and ballot conservation at reporting-unit, county, and state level.
- Let Stein or Oliver win a county or reporting unit when that named candidate's modeled votes genuinely exceed both major candidates.
- Add named third-party plurality colors and an explicit legend without changing the Harris versus Trump Shift view.
- Treat residual Other/write-in only as an aggregate category. It may receive a distinct aggregate marker if it exceeds both major candidates, but it may never be described as one candidate winning.
- Keep the certified statewide-only residual honest and off-map.
- Add adversarial tests for impossible ballots, order dependence, geography leakage, and false plurality coloring.

## v0.27C: Comparison and polish

Status: planned

- Compare certified and scenario contribution structures without duplicating the inspector.
- Refine copy, keyboard movement, selection handoff, and narrow-screen density.
- Use browser evidence to decide whether any additional visual form earns space.

## v0.28 preview: Demographic behavior

Demographic sliders start only after v0.27 is complete:

1. v0.28A defines the demographic evidence and model contract.
2. v0.28B adds group-specific turnout behavior.
3. v0.28C adds group-specific preference behavior.
4. v0.28D adds contribution and sensitivity explanations.

These controls must represent explicit user assumptions applied to disclosed demographic denominators. They may not imply that aggregate Census categories reveal individual candidate choice.
